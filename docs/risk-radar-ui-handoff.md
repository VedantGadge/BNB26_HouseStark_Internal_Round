# RiskRadar UI handoff

## Goal

Add a compact **RiskRadar** panel to the existing Publish workspace. It lets a
creator scan a selected completed export before package approval and inspect
concrete content risks.

RiskRadar is decision support. The UI must never describe a result as legal
approval, copyright clearance, independent fact checking, or a guarantee that
the video is safe to publish.

## Build location

Do **not** create a new route or a separate dashboard screen.

Create:

```text
frontend/components/workflow/risk-radar.jsx
```

Render it from:

```text
frontend/components/workflow/publish.jsx
```

Place the panel after **Select completed exports** and before **Save package
for review**. This makes RiskRadar a final, visible pre-publish checkpoint.

## Why Publish is the right place

`Publish` already loads completed exports. Each completed render supplies the
two IDs required by the backend:

```js
{
  id,
  asset_id,
  edit_version_id,
  platform,
  preset_name,
  supporting_copy,
  processing_status,
}
```

The panel submits the selected export's `asset_id` and `edit_version_id`. The
backend automatically uses the project's current saved script when
`script_version_id` is omitted.

## Backend contract

All paths are relative to the existing frontend API helper. It already adds
`/v1`, JSON headers, and the creator bearer token.

### Queue a scan

```http
POST /projects/{projectId}/risk-radar/scans
Idempotency-Key: generated by post(path, body, true)
```

```json
{
  "asset_id": "selected-render-asset-id",
  "edit_version_id": "selected-render-edit-version-id"
}
```

Optional field:

```json
{
  "script_version_id": "specific-saved-script-version-id"
}
```

For the MVP, omit `script_version_id`; the backend scans the current saved
script. Do not scan unsaved browser edits because the backend deliberately
reviews immutable saved content.

The success response is `202 Accepted`:

```json
{
  "id": "job-uuid",
  "status": "queued",
  "stage": "awaiting_worker",
  "error": null,
  "result": {}
}
```

### Poll the result

```http
GET /projects/{projectId}/risk-radar/scans/{jobId}
```

Poll every four seconds while `status` is `queued` or `running`. Stop on
`completed` or `failed`.

```json
{
  "id": "job-uuid",
  "status": "completed",
  "stage": "completed",
  "error": null,
  "result": {
    "summary": "Review the visible notification before release.",
    "reviewed_reference_count": 12,
    "review_readiness": "creator_review_required",
    "limitations": [
      "RiskRadar is decision support, not legal advice, copyright clearance, or independent fact checking.",
      "Visual findings are limited to persisted sampled-frame observations; the creator must review the final render."
    ],
    "findings": [
      {
        "category": "personal_data",
        "severity": "high",
        "title": "Possible email address in publishable content",
        "description": "RiskRadar detected a possible email address in script:section:section-1.",
        "recommendation": "Remove, mask, or explicitly confirm the sensitive detail.",
        "reference_ids": ["script:section:section-1"],
        "origin": "deterministic"
      }
    ]
  }
}
```

| Field | Values |
| --- | --- |
| `review_readiness` | `no_high_or_medium_risks_found`, `creator_review_required` |
| `severity` | `low`, `medium`, `high` |
| `category` | `personal_data`, `brand_policy`, `disclosure`, `content_mismatch`, `visual_review`, `accessibility` |
| `origin` | `deterministic`, `model` |

## Component API

```jsx
<RiskRadarPanel
  projectId={projectId}
  completedExports={completedExports}
  disabled={action.busy || state.stage === "published"}
/>
```

Keep the selected export in local component state. Do not read the surrounding
Publish form's checkbox DOM values; the scan must use one exact source asset
and immutable edit version.

Start with the first completed export selected. Make the selector labels easy
to understand, for example `Instagram · instagram_reel`.

## Implementation outline

```jsx
"use client";

import { useState } from "react";
import { useQuery } from "@tanstack/react-query";
import { apiFetch, post } from "@/lib/api";
import { Field, Status, useAction } from "./common";

export function RiskRadarPanel({ projectId, completedExports, disabled }) {
  const [selectedRenderId, setSelectedRenderId] = useState("");
  const [jobId, setJobId] = useState(null);
  const action = useAction();
  const selected =
    completedExports.find((item) => item.id === selectedRenderId) ||
    completedExports[0];

  const scan = useQuery({
    queryKey: ["risk-radar", projectId, jobId],
    queryFn: () => apiFetch(`/projects/${projectId}/risk-radar/scans/${jobId}`),
    enabled: Boolean(jobId),
    refetchInterval: (query) =>
      ["completed", "failed"].includes(query.state.data?.status)
        ? false
        : 4000,
  });

  async function runScan() {
    if (!selected) return;
    const queued = await post(
      `/projects/${projectId}/risk-radar/scans`,
      { asset_id: selected.asset_id, edit_version_id: selected.edit_version_id },
      true,
    );
    setJobId(queued.id);
  }

  // Render empty, loading, failure, and completed states.
}
```

Use `post(path, body, true)`, not plain `post(path, body)`. The `true` makes
the existing API helper persist an idempotency key, avoiding duplicate AI scans
after double-clicks or transient browser failures.

## Required UI states

### Empty

When there are no completed exports, render:

> Finish and verify a platform export before running RiskRadar.

Do not show the Run button.

### Ready

Show:

- Heading: **Pre-publish RiskRadar**
- Copy: “Review saved script, captions, source evidence, and brand rules before package approval.”
- Export selector
- Primary action: **Run RiskRadar**
- Muted disclaimer: “This is a creator review tool, not publishing approval or legal clearance.”

### Queued or running

Disable the selector and button. Display a polite live status:

```text
RiskRadar is reviewing saved content…
```

Use `aria-live="polite"` and surface `scan.data.stage` when available.

### Failed

Show `scan.data.error` and **Try again**. Retry by submitting a new scan,
rather than using `/jobs/{jobId}/retry`; the creator may have selected a new
export since the failed request.

### Completed: no high or medium risks

Show a green badge:

```text
No high or medium risks found
```

Show the summary and limitations too. Never show “Safe to publish.”

### Completed: creator review required

Show an amber/red badge:

```text
Creator review required
```

Render findings in severity order: high, medium, low.

## Finding cards

Each finding should show:

```text
[HIGH] Personal data · Detected rule
Possible email address in publishable content
RiskRadar detected a possible email address in script:section:section-1.
Recommended action: Remove, mask, or explicitly confirm the sensitive detail.
Evidence: script:section:section-1
```

- Use text and color for severity; do not rely on color alone.
- `high` uses error/destructive styling; `medium` warning styling; `low` muted
  informational styling.
- Label `origin: deterministic` as **Detected rule** and `origin: model` as
  **AI review**. Do not call either result “verified.”
- Render `reference_ids` as readable chips. They are display-only in this MVP.
- Put `limitations` below the findings in a collapsed **What RiskRadar cannot
  verify** details block.

## Integration steps in `publish.jsx`

1. Import `RiskRadarPanel` from `./risk-radar`.
2. Render it in the existing package form after completed exports are listed.
3. Pass `completedExports`, not all renders.
4. Preserve the current package-save and approval flow. RiskRadar must not
   block saving, review, export, or manual publishing in this MVP.
5. Clear `jobId` when the selected export changes, so old results cannot be
   mistaken for the new export's scan.

## Out of scope

- A new page, navigation item, environment variable, or database state.
- Automatic blur/crop, auto-rewrite, or package-approval blocking.
- Source-player seeking from the Publish page; show evidence reference chips
  only. Player seeking can be a later Editor enhancement.
- Unsaved script or edit drafts.
- Claims that every video frame was checked. The backend reviews persisted
  transcript segments and bounded sampled-frame observations.

## Acceptance checklist

- [ ] No completed exports produces a useful empty state.
- [ ] The selected export sends its exact `asset_id` and `edit_version_id`.
- [ ] Submission uses `post(..., true)`.
- [ ] Polling stops at `completed` or `failed`.
- [ ] High, medium, and low findings are visually and textually distinct.
- [ ] The UI renders summary, recommendations, reference chips, and limitations.
- [ ] A failed scan can be resubmitted.
- [ ] RiskRadar does not mutate content or block the existing package workflow.
- [ ] All loading, error, and completed states are keyboard accessible and screen-reader friendly.

## Manual demo test

Use a ready video with a saved script and completed export. Add
`guaranteed results` as a forbidden brand phrase, and include the same phrase
in a script section. Run RiskRadar and confirm the panel shows:

1. `Creator review required`.
2. A high-severity `brand_policy` finding.
3. The script/brand reference chip.
4. A recommendation to replace the phrase or update the approved brand brief.

For a visual demo, keep a fake email or notification visible near the first
second of the source video, so the bounded frame sampler is likely to record
it. This supplements—not replaces—the creator's final visual review.
